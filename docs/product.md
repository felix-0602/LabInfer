# 产品定义

## 定位

拍一张实验数据，AI 不只把数据算出来，还告诉你这组数据说明了什么、哪里可能不对、下次怎么改。

现有工具只做到「数据 → 结果」，我们补上「结果 → 结论」：规律、能证明什么、异常、改进建议。

**面向复现实验的学生，不是替人指导实验**：产品定位是帮复现者判断、理解自己的数据，不是充当实验设计的军师。AI 的解读语言按入门学生设计，从数据点到实验全貌由点到面展开（表达标准见 [wiki.md](wiki.md#表达标准)，M5 提示词与保底文案已按此落地，契约 0.8.0）。

**讲解阶梯**：学生做的实验难度可能只有 3 级，但讲解不止于 3 级。每条结论先在学生所在层讲清楚，再往上递一到两级上下文（为什么选这个指示剂、误差怎么分类、标准方法怎么要求、科研里怎么做），每一级都挂回学生自己的数据点，不讲脱离数据的知识。阶梯内容随模板沉淀，结构见 [wiki.md](wiki.md#讲解阶梯)。

## 目标用户

所有用户做的都是同一件事：**拿自己的实验数据和一个参照对比，判断结果对不对、说明了什么。**

- **主角（答辩故事用）**：复现文献实验的研究生或高年级本科生，参照物是论文里的曲线。
- **扩展人群**：写实验报告的本科生，参照物是教材或文献中的预期规律。

## 差异化

**真实竞对是专业工具链，不是通用大模型**：取数用 WebPlotDigitizer 手点，拟合作图用 Origin / Python，参考值回文献里翻，「结果正不正常、异常在哪、下一步改什么」靠经验判断。这些工具停在「数据 → 结果」；「结果 → 结论」没有工具，本产品补这一段，并把上游取数、拟合一起打通。

**和通用大模型的关键差距不在模型能力，在垂直的数据与算法层**——这层没有现成方案，是本项目的主要工作：

- 数据结构：实验上下文（角色绑定变量、三层参照、质控规则包）、带角色标注的数据集、类型化证据引用（见 [contracts.md](contracts.md)）。
- 确定性算法：坐标换算（线性 / 对数轴，报告校准残差）、scipy 拟合、格拉布斯离群检验（GB/T 4883）、M5 数字溯源校验器。

通用模型接上这层才能可靠工作；直接用的三个老问题由此被接管：

| 通用大模型直接用的问题 | 我们的接管方式 |
|---|---|
| 自己做算术和拟合，数字可能算错 | 计算全部交给代码，AI 只负责解读计算结果 |
| 不知道实验背景，结论空泛 | 先确定实验上下文（目的、原理、变量），再结合上下文分析 |
| 说「能证明什么」没有参照，容易编造 | 从文献曲线中取数作为参照，每条结论都要指向具体数据点 |

## 技术亮点（对外讲法）

答辩与报名材料用。左列是闭环里实际存在的机制，右列是对应的范式名称。

| 闭环里的机制 | 对外讲法 |
|---|---|
| 计算全部由代码完成，AI 只解读（[architecture.md](architecture.md) 核心原则） | Program-of-Thought / tool-use：LLM 从不当计算器，计算幻觉从机制上消除 |
| 结论挂类型化 evidence，数字必须能在分析结果中找到（[contracts.md](contracts.md)） | 可溯源 grounded generation：每条结论可点击回溯到具体数据点 |
| 三层参照（文献 / CRM / 法规限值）+ raw / transformed 空间声明 | 领域化 grounding：参照是带 DOI 溯源的数值，不是文档切片 |

规划中的增强（只作方向宣讲，不进 Must）：

- **Grounded Reflexion**：把 M5 已有的校验-回灌-降级正式化为「生成 → 评审 → 回灌」循环。差异点在反思信号来自确定性校验而不是模型自评：代码验事实（数字溯源、证据存在），小模型评表达（术语、建议可执行性）；事实失败回灌重生成，表达不合格只重写文案。回灌次数有硬上限（契约现为 1 次），仍失败降级为模板文案，演示不因重试卡住。

## 演示案例

**HCl 标定与碱灰总碱度**（GB/T 601-2016 无水碳酸钠法，对应武汉工程大学《分析化学实验》实验 3）：三份平行标定 HCl 浓度，再对碱灰试液做三份平行滴定，测总碱度（以 Na₂O 计）并检查精密度。

- 数据来源：团队成员的真实手写数据记录页（已存为 `design/assets/DEMO-01.jpg`）。M1 识别缓存按这张图的 sha256 烘焙，演示时上传原图即命中，不依赖网络与模型。
- 能证明什么：c̄(HCl) 是否可靠（滴定体积—称样量过原点线性 + 相对平均偏差），以及碱灰总碱度 w(Na₂O)。
- 典型异常（数据里真实存在）：标定相对平均偏差 1.31%、测定 2.14%，都超过 ≤0.2% 的教学要求；三份总碱度全部高于纯 Na₂CO₃ 理论值 58.47%，第 2 份偏离最大，推演「少滴 2 mL」即回落到约 58.6%，指向终点过读。
- 参照分两类：数值参照（理论值由 M(Na₂O)/M(Na₂CO₃) 算出，条文依据 GB/T 601-2016 与 GB/T 4883）；曲线参照（HCl 滴定 Na₂CO₃ 的滴定曲线：理论曲线由 M4 从碳酸 pKa 按电荷平衡计算，文献曲线由 M2 从教材或论文的图中取数，二者叠加）。学生的终点是离散体积，没有曲线；把终点按 ΔV = 实测 − 化学计量点放到滴定曲线上，曲线参照才和学生数据接上。
- 演示图表三张，都只用真实数据或确定性计算：
  1. **滴定曲线叠图**（主图）：理论曲线 + 文献曲线 + 甲基橙变色区 + 学生三份标定终点（ΔV 以三份平均浓度为零点，反映离散而非绝对偏差）。未煮沸时 CO₂ 缓冲让突跃变缓，甲基橙在计量点前约 0.15 mL 就开始变色，终点难判是离散的一部分来源；但 p2（−0.65 mL，终点处 pH 约 5.0，应仍为黄色）和 p3（+0.52 mL，pH 约 3.1，已过红）分别落在变色区两侧之外，指向终点判断或读数，而不只是指示剂。推演拖动「残留 CO₂」到煮沸，变色起点移到计量点后约 0.02 mL，把「近终点煮沸」这条建议变成看得见的结果。
  2. **平行样精密度条带**：三份标定、三份测定相对 ±0.2% 允许带的位置，对应两条未通过的质控。
  3. **误差预算**：天平、滴定管读数等仪器项合成的预期相对偏差，对比实测 1.31%，说明误差来自操作。
- M2 在本案例取的是滴定曲线图，曲线类模板（碘钟等）同样适用。
- 不允许编造演示数据；换实验 = 换一份真实记录 + 一条模板。

## 闭环

上传我的数据 + 文献截图 → 两条曲线叠在一起对比 → AI 给出结论和建议 → 推演按建议修改后的结果 → 导出报告段落

| | 2. 文献曲线截图取数，坐标校准后输出数据（通用能力，曲线类模板的演示亮点） |
| | 3. 实验数据和参照叠图，代码拟合（演示案例：滴定体积—称样量过原点拟合，浓度与总碱度全由代码算出；终点放上理论 + 文献滴定曲线） |
| | 4. AI 解读：规律、能证明什么、异常点、改进建议，每条都指向数据点 |
| **Should** | 5. 参数推演：选中一条建议后画出预测曲线（替代 3D 实验台，把建议变成看得见的结果） |
| | 6. 导出报告「结果与讨论」段落和图表 |
| **Could** | 7. 虚拟实验台（取代原 3D 实验台，见下）、实验模板库 |
| **Won't** | 账号体系、协作、仪器谱图解析（DSC/GPC/红外）、原生 App |

### Could 7：虚拟实验台

给 AI 一个端到端验证的地方，也给学生一个身临其境的复盘场景。

- **AI 验证假设**：M5 提出的每个异常原因（终点滴过、读数误差、基准物吸水、未煮沸驱 CO₂）都翻译成虚拟台上的一组参数，用学生的真实称样量与浓度重跑实验，看能否复现学生的数据形态。复现得了，结论标「已验证」；复现不了，结论降级或撤回。例：基准物吸水只会让三份浓度同向偏高，拉高平均值但不拉大相对平均偏差，解释不了 1.31% 的离散；要把总碱度从 58.47% 推到 60.63%，需要约 3.7% 的系统偏差，远超「吸水 1%」。这是由确定性计算给 AI 的反思信号，和 Grounded Reflexion 同源。
- **学生复盘**：在虚拟滴定管上重走自己的三份滴定，终点前后逐滴显示 pH 与颜色，看到自己的终点偏离 0.5～0.65 mL 时，溶液要么还没进变色区（p2 少滴），要么已经越过（p3 多滴）。
- **实现路线：自建，并以 MCP 服务器对外提供。** 复用 M4 的滴定曲线模型（电荷平衡，确定性），不另写一套化学；前端在 M8 里画滴定管、锥形瓶与颜色。工具集：`setup_titration`（按学生称样量、水量、HCl 浓度布置）、`add_titrant`、`read_ph` / `observe_color`（读 pH 与甲基橙颜色）、`boil`（设残留 CO₂ 比例）、`replay_with_fault`（注入吸水 x%、多滴 ΔV、读数误差等假设故障后重跑，返回与学生实测的对比）。M5 通过工具调用使用它；任何支持 MCP 的客户端也能直接接入，答辩可现场演示「换一个 AI 也能用这个实验台」，对应赛道「开源方法」。
- **验证状态**：每条异常类结论带「已验证 / 被否定 / 未验证」与调用记录作为证据，M8 显示在结论卡片上。每条结论的工具调用有硬上限（暂定 3 次），超限或 MCP 不可用即降级为「未验证」，演示不因验证卡住。M5 需扩展 `llm.chat()` 支持工具调用（归 z）。调研过的现成平台都不适合由程序驱动：ChemCollective Virtual Lab 可离线运行但许可为 CC BY-NC-ND 3.0（禁止修改）且没有调用接口，只适合作为外链给学生自练；PhET 的酸碱模拟没有滴定过程，其 GitHub 仓库已标注停止维护；开源的 Open Experiment Space（MIT）带滴定管但尚处早期（5 次提交）。
- 边界：虚拟台只验证「这个原因能不能解释这组数据」，不替代真实实验，也不生成演示数据。
