# 产品定义

## 定位

拍一张实验数据，AI 不只把数据算出来，还告诉你这组数据说明了什么、哪里可能不对、下次怎么改。

现有工具只做到「数据 → 结果」，我们补上「结果 → 结论」：规律、能证明什么、异常、改进建议。

**面向复现实验的学生，不是替人指导实验**：产品定位是帮复现者判断、理解自己的数据，不是充当实验设计的军师。AI 的解读语言按入门学生设计，从数据点到实验全貌由点到面展开（语言调整落在 M5，尚未做）。

## 目标用户

所有用户做的都是同一件事：**拿自己的实验数据和一个参照对比，判断结果对不对、说明了什么。**

- **主角（答辩故事用）**：复现文献实验的研究生或高年级本科生，参照物是论文里的曲线。
- **扩展人群**：写实验报告的本科生，参照物是教材或文献中的预期规律。

## 差异化

**真实竞对是专业工具链，不是通用大模型**：取数用 WebPlotDigitizer 手点，拟合作图用 Origin / Python，参考值回文献里翻，「结果正不正常、异常在哪、下一步改什么」靠经验判断。这些工具停在「数据 → 结果」；「结果 → 结论」没有工具，本产品补这一段，并把上游取数、拟合一起打通。

**和通用大模型的关键差距不在模型能力，在垂直的数据与算法层**——这层没有现成方案，是本项目的主要工作：

- 数据结构：实验上下文（角色绑定变量、三层参照、质控规则包）、带角色标注的数据集、类型化证据引用（见 [contracts.md](contracts.md)）。
- 确定性算法：坐标换算（线性 / 对数轴，报告校准残差）、scipy 拟合、格拉布斯离群检验（GB/T 4883）、M5 数字溯源校验器。

通用模型接上这层才能可靠工作；直接用的三个老问题由此被接管：

| 通用大模型直接用的问题 | 我们的接管方式 |
|---|---|
| 自己做算术和拟合，数字可能算错 | 计算全部交给代码，AI 只负责解读计算结果 |
| 不知道实验背景，结论空泛 | 先确定实验上下文（目的、原理、变量），再结合上下文分析 |
| 说「能证明什么」没有参照，容易编造 | 从文献曲线中取数作为参照，每条结论都要指向具体数据点 |

## 技术亮点（对外讲法）

答辩与报名材料用。左列是闭环里实际存在的机制，右列是对应的范式名称。

| 闭环里的机制 | 对外讲法 |
|---|---|
| 计算全部由代码完成，AI 只解读（[architecture.md](architecture.md) 核心原则） | Program-of-Thought / tool-use：LLM 从不当计算器，计算幻觉从机制上消除 |
| 结论挂类型化 evidence，数字必须能在分析结果中找到（[contracts.md](contracts.md)） | 可溯源 grounded generation：每条结论可点击回溯到具体数据点 |
| 三层参照（文献 / CRM / 法规限值）+ raw / transformed 空间声明 | 领域化 grounding：参照是带 DOI 溯源的数值，不是文档切片 |

规划中的增强（只作方向宣讲，不进 Must）：

- **Grounded Reflexion**：把 M5 已有的校验-回灌-降级正式化为「生成 → 评审 → 回灌」循环。差异点在反思信号来自确定性校验而不是模型自评：代码验事实（数字溯源、证据存在），小模型评表达（术语、建议可执行性）；事实失败回灌重生成，表达不合格只重写文案。回灌次数有硬上限（契约现为 1 次），仍失败降级为模板文案，演示不因重试卡住。

## 演示案例

**HCl 标定与碱灰总碱度**（GB/T 601-2016 无水碳酸钠法，对应武汉工程大学《分析化学实验》实验 3）：三份平行标定 HCl 浓度，再对碱灰试液做三份平行滴定，测总碱度（以 Na₂O 计）并检查精密度。

- 数据来源：团队成员的真实手写数据记录页（已存为 `design/assets/DEMO-01.jpg`）。M1 识别缓存按这张图的 sha256 烘焙，演示时上传原图即命中，不依赖网络与模型。
- 能证明什么：c̄(HCl) 是否可靠（滴定体积—称样量过原点线性 + 相对平均偏差），以及碱灰总碱度 w(Na₂O)。
- 典型异常（数据里真实存在）：标定相对平均偏差 1.31%、测定 2.14%，都超过 ≤0.2% 的教学要求；三份总碱度全部高于纯 Na₂CO₃ 理论值 58.47%，第 2 份偏离最大，推演「少滴 2 mL」即回落到约 58.6%，指向终点过读。
- 参照不来自文献曲线：理论值由 M(Na₂O)/M(Na₂CO₃) 算出，条文依据 GB/T 601-2016 与 GB/T 4883。M2 曲线取数仍是通用能力，供碘钟等曲线类模板使用。
- 不允许编造演示数据；换实验 = 换一份真实记录 + 一条模板。

## 闭环

上传我的数据 + 文献截图 → 两条曲线叠在一起对比 → AI 给出结论和建议 → 推演按建议修改后的结果 → 导出报告段落

（滴定演示的参照是理论值与限值，闭环中「文献截图」一步不经过 M2。）

## 功能优先级（MoSCoW）

| 级别 | 功能 |
|---|---|
| **Must** | 1. 手写实验记录拍照，识别成表格，可以手动校正 |
| | 2. 文献曲线截图取数，坐标校准后输出数据（通用能力，曲线类模板的演示亮点） |
| | 3. 实验数据和参照叠图，代码拟合（演示案例：滴定体积—称样量过原点拟合，浓度与总碱度全由代码算出） |
| | 4. AI 解读：规律、能证明什么、异常点、改进建议，每条都指向数据点 |
| **Should** | 5. 参数推演：选中一条建议后画出预测曲线（替代 3D 实验台，把建议变成看得见的结果） |
| | 6. 导出报告「结果与讨论」段落和图表 |
| **Could** | 3D 实验台（只做静态场景，高亮出问题的环节）、实验模板库 |
| **Won't** | 账号体系、协作、仪器谱图解析（DSC/GPC/红外）、原生 App |
