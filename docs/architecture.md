# 系统架构

功能优先级见 [product.md](product.md)，字段级数据格式见 [contracts.md](contracts.md)。

## 核心原则

**计算全部由 M4 用代码完成，AI（M5）只解读 M4 的结果，不自己算数。** 这是和通用大模型的差异，也是结论可信的依据。

## 数据流

```
 [手写记录照片] ──► M1 记录识别 ──► 数据集(我的) ─┐
                                                   │
 [文献曲线截图] ──► M2 曲线取数 ──► 数据集(文献) ─┼──► M4 计算对比 ──► 分析结果 ──► M5 AI解读 ──► 结论列表
                                                   │         ▲                                   │
 [实验模板/信息] ─► M3 实验上下文 ────────────────┘         └──────── M6 参数推演 ◄── 可推演的结论
                                                                                                 │
                                            M7 报告导出 ◄── 汇总以上全部 ◄───────────────────────┘
                              M8 前端工作台：把以上模块串成一个页面流程
```

## 系统形态（提议，待确认）

- **后端**：一个 Python 服务（FastAPI），每个模块是一组路由，挂在 `/api/m{编号}/` 下。M2、M4 等都依赖 numpy、OpenCV、开源 VLM，放在同一个进程里，部署最简单。
- **共享存储**：数据集和实验上下文存成 JSON 文件，通过 `/api/datasets/`、`/api/contexts/` 读写。哪个模块产出数据集，就由哪个模块写入存储。
- **前端**：M8 是独立的单页应用，只通过 HTTP 调后端，不直接读写文件。

接口的具体定义见 [contracts.md](contracts.md#http-接口)。

## 模块

| 模块 | 优先级 | 负责人 | 输入 | 输出 |
|---|---|---|---|---|
| M1 记录识别 | Must | z | 手写记录照片 | 数据集（每格带置信度） |
| M2 曲线取数 | Must | c | 论文图表截图、文献信息 | 数据集（带文献来源） |
| M3 实验上下文 | 支撑 | z | 实验名称、目的、变量、模型、关联文献 | 实验上下文 |
| M4 计算对比 | Must | z | 数据集 + 实验上下文 | 分析结果 |
| M5 AI 解读 | Must | z | 实验上下文 + 分析结果 | 结论列表 |
| M6 参数推演 | Should | z | 拟合参数 + 一条可推演的结论 | 预测曲线 |
| M7 报告导出 | Should | z | 上下文、分析结果、结论、图表 | 报告段落（Markdown / Word）和图片 |
| M8 前端工作台 | 支撑 | c | 以上所有模块的输出 | 页面流程 |

### M1 记录识别
- 两段式识别：先让 VLM 做版面分析，找出每张表格的边界框（含表格上方的标题/备注行）；再逐表裁剪、逐表识别，行结果合并。整页只有一张表或版面分析失败时回退整页单次识别。多表记录页（先标定后测定）整页单次识别会漏表，实测拆开后识别稳定性显著提高。
- 视觉模型用 glm-5.3-flash。识别结果在边界做两类归一：series 别名映射到契约枚举（模型常写「样品：碱灰」「标定」），全空值行直接丢弃。
- 手写数字容易认错（本页实测：1.5919 被多轮读成 0.5999，置信度也低），低置信度的格子由用户在 M8 里校正，所以校正界面是必需的；演示走缓存命中时识别结果是预先校正好的。

### M2 曲线取数

**负责**
- 接收论文图表截图和文献信息（DOI、图号），保存原图。
- 识别：用开源 VLM 读出坐标轴刻度、轴类型、轴标题和图例，给出校准建议和曲线列表。只负责「读」，不做数值换算。
- 提取：按用户确认的校准和选定的曲线，用 OpenCV 按颜色找出数据点的像素位置；手动模式直接使用用户点取的像素。
- 换算：用确定性代码把像素坐标换算成数据坐标（线性轴、对数轴），并报告校准残差。公式见 [contracts.md](contracts.md#坐标换算)。
- 输出一个 `source: literature` 的数据集，并写入共享存储。

**不负责**
- 拟合、单位换算、物理量推导，这些由 M4 负责。M2 输出的数值就是坐标轴上标的数：图上画的是 ln(1/t)，就输出 ln(1/t)。
- 判断这条曲线和实验是什么关系，由 M3 在实验上下文里声明。
- 页面交互。拖动校准点、放大镜、手动点取都在 M8，M2 只接收结果。

**流程**：上传图片 → 识别 → M8 让用户确认校准 → 提取 → 数据集

**失败与兜底**
- VLM 不可用或识别失败：识别接口返回 503，M8 进入手动校准，由用户自己放 4 个校准点。
- 按颜色分离失败（曲线重叠、颜色相近）：提取接口返回空点列并附带警告，M8 切换到手动点取。
- 演示保底：演示用截图的识别结果预先缓存，按图片哈希命中后直接返回，不调用 VLM。

### M3 实验上下文
演示实验（HCl 标定与碱灰总碱度，见 [product.md](product.md#演示案例)）做成预置模板，用户只需确认。

### M4 计算对比
- Python + numpy/scipy。模型按 contracts 的[模型注册表](contracts.md#模型注册表)实现（`linear_calibration`、`arrhenius`、`titration_standardization`），新增模型 = 新增一个子类 + 注册一行，路由与契约不变。
- 离群点用格拉布斯检验（GB/T 4883）判定。
- 只输出数值结果，不输出图表配置，图表由 M8 根据分析结果绘制。

### M5 AI 解读
- 只接收结构化的分析结果，不接收原始图片。
- 防编造：① 结论里出现的数字必须能在分析结果里找到，用代码校验；② 每条结论必须引用数据点。

### M6 参数推演
只有能写成参数的建议（温度、浓度）才能推演。「把试管洗干净」这类建议标记为不可推演，前端不显示推演按钮。

### M8 前端工作台

页面设计与交互见 [design/index.html](../design/index.html)。

**负责**
- S0–S5 全部页面和交互。
- 页面状态：当前实验、步骤进度、各步已确认的数据。状态只存在浏览器内存里，刷新后从后端重新拉取。
- 编排调用：按步骤调用 M1–M7 的接口，把上一个模块的输出原样交给下一个模块，不改写内容。
- 用户校正：M1 低置信度格子的修改、M2 校准点的拖动和手动点取，结果提交回对应模块。
- 图表绘制：根据 M4 的分析结果绘制对比图。
- 联动：点结论卡片，高亮它引用的数据点；拖推演滑块，调用 M6 并画出预测曲线。
- 兜底界面：接口失败时给出提示、切换到手动模式、加载演示保底数据。

**不负责**
- 任何科学计算：拟合、单位换算、Ea、残差都以 M4 返回的结果为准，前端即使能算也不算。唯一的例外是 M2 画布上光标处的坐标读数：它只用于显示，公式与 M2 相同，提交时以 M2 的计算结果为准。
- 数据持久化，由后端负责。
- 调用 VLM 和 LLM，这是 M1、M2、M5 的事。
- 生成报告正文，由 M7 负责；导出页只做预览和选项。

**技术**：Vite + React + TypeScript。图表用 SVG 自绘，因为设计稿里的温度刻度尺、残差引线、推演外推线这些定制元素，用通用图表库反而难做。

## 开发顺序

| 顺序 | 内容 | 说明 |
|---|---|---|
| 1 | 定稿 contracts.md、M3 预置模板 | 所有模块都依赖它 |
| 2 | M4、M2、M1 并行 | M4 是中枢，先用手动录入的数据开发；M2 风险最高，最早开始 |
| 3 | M5 | 等 M4 的输出格式稳定后再做 |
| 4 | M8 串联 | 从第 2 步起逐步接入 |
| 5 | M6 → M7 | 核心闭环跑通以后再做 |

## 演示保底

为 M1、M2 准备好已经校正过的结果作为备份。演示时网络或模型出问题，也能把流程走完。

- M1：`scripts/seed_demo.py` 按数据记录页照片（`design/assets/DEMO-01.jpg`）的 sha256 烘焙识别缓存，上传原图即命中，不调 VLM。照片是团队真实记录，缓存内容与种子数据一致。烘焙走白名单政策：只有 `server/demo_cache/manifest.json` 登记的图片写进入库的演示缓存，其余识别结果写不入库的运行时缓存（`server/data/runtime_cache/`），用户数据不进 git，读取两处都查。
- M2：0.7.0 起滴定演示恢复经过 M2——取文献滴定曲线作参照（见 [contracts.md](contracts.md#experimentcontext-实验上下文)「滴定曲线参照」）。识别接口按图片 sha256 命中 `demo_cache/m2/` 的机制已就绪（与 M1 同一套白名单政策），演示曲线的烘焙条目待 M8 接入文献取数屏后补齐。
- M2、M8 的代码与设计稿不在演示切换范围内，归各自负责人；接口约束见 [contracts.md](contracts.md#演示切换对-m2--m8-的边界约束-050)。
