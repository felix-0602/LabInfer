# 系统架构

功能优先级见 [product.md](product.md)，字段级数据格式见 [contracts.md](contracts.md)。

## 核心原则

**计算全部由 M4 用代码完成，AI（M5）只解读 M4 的结果，不自己算数。** 这是和通用大模型的差异，也是结论可信的依据。

## 数据流

```
 [手写记录照片] ──► M1 记录识别 ──► 数据集(我的) ─┐
                                                   │
 [文献曲线截图] ──► M2 曲线取数 ──► 数据集(文献) ─┼──► M4 计算对比 ──► 分析结果 ──► M5 AI解读 ──► 结论列表
                                                   │         ▲                                   │
 [实验模板/信息] ─► M3 实验上下文 ────────────────┘         └──────── M6 参数推演 ◄── 可推演的结论
                                                                                                 │
                                            M7 报告导出 ◄── 汇总以上全部 ◄───────────────────────┘
                              M8 前端工作台：把以上模块串成一个页面流程
```

## 模块

| 模块 | 优先级 | 负责人 | 输入 | 输出 |
|---|---|---|---|---|
| M1 记录识别 | Must | zcode | 手写记录照片 | 数据集（每格带置信度） |
| M2 曲线取数 | Must | Claude | 论文图表截图、文献信息 | 数据集（带文献来源） |
| M3 实验上下文 | 支撑 | zcode | 实验名称、目的、变量、模型、关联文献 | 实验上下文 |
| M4 计算对比 | Must | zcode | 数据集 + 实验上下文 | 分析结果 |
| M5 AI 解读 | Must | zcode | 实验上下文 + 分析结果 | 结论列表 |
| M6 参数推演 | Should | zcode | 拟合参数 + 一条可推演的结论 | 预测曲线 |
| M7 报告导出 | Should | zcode | 上下文、分析结果、结论、图表 | 报告段落（Markdown / Word）和图片 |
| M8 前端工作台 | 支撑 | Claude | 以上所有模块的输出 | 页面流程 |

### M1 记录识别
- 用开源 VLM（如 Qwen-VL）把照片直接转成数据集 JSON。
- 手写数字容易认错（1 和 7、小数点、负号），低置信度的格子由用户在 M8 里校正，所以校正界面是必需的。

### M2 曲线取数
1. VLM 识别坐标轴刻度和图例，给出初始校准点。
2. 用户在 M8 里确认或拖动校准点。
3. 按曲线颜色提取像素（OpenCV）。
4. 用确定性代码把像素坐标换算成数据坐标（支持线性轴和对数轴）。

坐标换算不交给 VLM 去猜。曲线重叠、按颜色分离失败时，退回到用户在图上手动点取。

### M3 实验上下文
银镜反应动力学做成预置模板，用户只需确认。

### M4 计算对比
- Python + numpy/scipy。第一版只实现 Arrhenius 模型，接口要留成可以扩展。
- 异常点用残差阈值判定。
- 只输出数值结果，不输出图表配置，图表由 M8 根据分析结果绘制。

### M5 AI 解读
- 只接收结构化的分析结果，不接收原始图片。
- 防编造：① 结论里出现的数字必须能在分析结果里找到，用代码校验；② 每条结论必须引用数据点。

### M6 参数推演
只有能写成参数的建议（温度、浓度）才能推演。「把试管洗干净」这类建议标记为不可推演，前端不显示推演按钮。

### M8 前端工作台
- 页面设计与交互见 [design/index.html](../design/index.html)。
- 网页端，画图用 ECharts 或 Plotly。
- 页面流程：上传 → 校正 → 对比图 → 结论面板 → 推演 → 导出。
- 结论面板和图表联动：点一条结论，高亮它引用的数据点。

## 开发顺序

| 顺序 | 内容 | 说明 |
|---|---|---|
| 1 | 定稿 contracts.md、M3 预置模板 | 所有模块都依赖它 |
| 2 | M4、M2、M1 并行 | M4 是中枢，先用手动录入的数据开发；M2 风险最高，最早开始 |
| 3 | M5 | 等 M4 的输出格式稳定后再做 |
| 4 | M8 串联 | 从第 2 步起逐步接入 |
| 5 | M6 → M7 | 核心闭环跑通以后再做 |

## 演示保底

为 M1、M2 准备好已经校正过的结果作为备份。演示时网络或模型出问题，也能把流程走完。
